# CG-D 탐색 적용 문의에 대한 답변

측정해 주신 시간·탐색 성능 자료와 여섯 가지 문의에 대한 답변입니다. 말씀하신 변경 중 코드로 반영 가능한 항목은 모두 저장소에 반영했으며, 사전 지도 제작 경로(`gsa_fast.py`, `prebuild_from_bag.sh`)와 CG-D 원본 코드는 변경하지 않았습니다.

## 요약

| 문의 | 답변 | 조치 |
|---|---|---|
| 1. 탐색 중 RAM 제외 | 가능합니다. 단, 목표 이름을 지정하는 경우에 한합니다 | `--no-ram` 추가, `run_search.sh` 기본값으로 적용 |
| 2. 그리기 분리 | 분리했습니다 | 서버는 상자·마스크·이름만 전송, 받는 쪽에서 그림 |
| 3. `GSA_RAM_GPU=1` 기본 | 실시간 서비스에는 기본으로 적용했습니다 | 태그 257/257장 일치 확인 |
| 4. CLIP 묶음 처리 | 적용했습니다 | 로컬 기준 CLIP 시간 약 1/3 |
| 5. 단계별 시간 | 아래 표를 참고해 주십시오 | 실행 결과에 `timing` 추가 |
| 6. 서버 운영 분담 | 제안을 아래에 적었습니다 | 합의 필요 |

## 1. 탐색 중 RAM 제외

**목표 이름을 넣어 탐색한다면 제외해도 됩니다.** 질의 이름과 정확히 일치하는 검출만 인정하는 판정에서는 오히려 탐지율이 올랐습니다. 다만 목표 이름이 없을 때 household 목록 밖의 물체를 찾지 못하는 것이 RAM을 뺄 때의 가장 큰 손실입니다.

평가는 기준표의 물체가 사진에 보이는 경우를 대상으로 했고(406호 122장 357건, 412호 135장 806건), 게이트는 신뢰도 0.25, 목표 이름 0.4입니다. 말씀하신 정차 단위 판정과는 기준이 다릅니다.

| 탐지율 (406호 / 412호) | RAM 포함 | RAM 제외 |
|---|---|---|
| **목표 지정, 이름 정확히 일치** | 0.451 / 0.459 | **0.625 / 0.494** |
| 목표 지정, 동의어 인정 | 0.672 / 0.522 | 0.625 / 0.494 |
| 목표 없음, 동의어 인정 | 0.754 / 0.553 | **0.532 / 0.366** |

목표 지정 시 범주별로 크게 달라진 항목입니다(이름 정확히 일치 기준).

| 범주 | 방 | RAM 포함 → 제외 | 내용 |
|---|---|---|---|
| blanket | 406 / 412 | 0.531 → 0.984 / 0.649 → 0.797 | 개선 |
| desk | 406 / 412 | 0.074 → 0.328 / 0.356 → 0.496 | RAM 포함 시 `computer desk`로 나오던 경우가 줄어듦 |
| chair | 412 | 0 → 0.72 | 개선 |
| **window** | 412 | **0.50 → 0.048** | 악화. 확인한 사진에서 신뢰도가 0.38~0.39로 0.4 게이트 근처이고, 일부는 door로 나옴 |

말씀하신 이름 통일 문제도 이 자료에서 확인됩니다. 동의어 판정으로 검출된 것 중 질의 이름 그대로 나온 비율은 RAM 포함 시 67%(161/240, 406호)와 88%(370/421, 412호)였고, RAM 제외 시 두 방 모두 100%(223/223, 398/398)였습니다. 다만 원인이 이름 경쟁인지는 이 측정으로 확인하지 못했습니다.

**RAM을 뺄 때 잃는 것**

- **household 목록 밖의 물체:** 목표 없음 조건에서 toilet paper 0.869 → 0, 0.833 → 0, hanger 0.467 → 0, bulletin board 0.689 → 0, window 0.786 → 0으로 떨어졌습니다. 목표 이름에 넣으면 toilet paper(1.0)와 hanger(0.683)는 되돌아오지만, window는 위 표처럼 낮게 남고 bulletin board는 이름 정확히 일치 기준으로 0입니다.
- **목표가 비어 있는 동안의 어휘:** `SearchTargets`가 비어 있으면 household 목록만 남습니다. 메시지 주석의 "perception uses its own vocabulary"가 RAM 포함을 전제로 한다면 조정이 필요합니다.
- **목표가 아닌 물체의 이름 다양성:** 나오는 이름 수가 406호 36 → 24, 412호 54 → 30개로 줄었습니다.
- **일반 이름의 오검출:** 목표 지정 시 기준표 밖 범주의 오검출률이 0.116 → 0.161, 0.176 → 0.208로 늘었습니다(406호 cabinet 37 → 75장). 기준표 범주의 오검출률은 0.042 → 0.032, 0.079 → 0.079로 늘지 않았습니다.

**사전 지도 연결:** `object_id` 연결은 이름이 아니라 CLIP과 위치 점수를 사용하므로, 검출만 있으면 연결될 수 있습니다. 기준표 물체 위에 이름과 무관하게 검출이 겹친 비율은 목표 지정 시 0.911 → 0.913, 0.769 → 0.767로 거의 같았습니다. 다만 RAM을 뺀 상태로 fusion을 재생해 연결률을 잰 것은 아니므로, 로봇 시험에서 확인이 필요합니다.

**사용법**

```bash
bash robot/scripts/run_search.sh <objects.json>             # RAM 제외 (기본)
CGD_RAM=1 bash robot/scripts/run_search.sh <objects.json>   # RAM 포함
python3 cgd_live_node.py --server 127.0.0.1:47000 --no-ram  # 노드 직접 실행
```

## 2. 그리기 분리

- `CGDEngine.run`은 더 이상 그림을 그리지 않으며, 결과에서 `annotated`를 뺐습니다.
- `cgd_server.py`는 상자, 마스크, 이름, CLIP만 보냅니다. 그림은 `cgd_wire.draw_detections(image, objects)`로 받는 쪽에서 그립니다(cv2와 numpy만 필요).
- `cgd_live_node.py`는 `/cg_d/annotated` 구독자가 있거나 `--save-dir`을 지정한 경우에만 그립니다.
- 그리기 시간은 사진당 로컬 0.20 → 0.033 s(406호), 0.37 → 0.059 s(412호)입니다. 서버에서는 새 함수가 0.13~0.18 s였습니다.

**주의할 점**

- 검출 화면에는 최종 물체만 나옵니다. 이전 화면에 있던 wall, floor, 신뢰도 0.25 미만 검출은 나오지 않습니다.
- 통신 형식이 바뀌어 서버와 로봇 PC의 코드 버전을 함께 맞춰야 합니다.
- `annotated`를 사용하거나 함수를 대체하는 스크립트는 수정이 필요합니다.

## 3. `GSA_RAM_GPU=1` 기본 적용

**실시간 서비스에는 기본으로 적용했습니다**(`server/start_cgd_server.sh`, `GSA_RAM_GPU=0`으로 되돌릴 수 있음).

- **태그 일치:** 같은 서버에서 CPU와 GPU로 RAM을 돌린 결과, 사진 257장의 태그가 모두 같았습니다. 태그가 같으면 DINO에 들어가는 이름 목록도 같습니다. 이후 단계의 CPU·GPU 전체 비교는 따로 하지 않았습니다.
- **시간:** RAM이 사진당 CPU 5.70 / 5.32 s에서 GPU 0.27 / 0.25 s로 줄었습니다(406호 / 412호, 8스레드, 서버 부하 약 130).
- **메모리:** A100 MIG 조각에서 257장 × 3조건을 메모리 부족 없이 처리했습니다.
- **적용 범위:** 사전 지도 제작은 재현성을 위해 그대로 두었습니다. RTX 4060(8 GB)에서는 이전 시험에서 메모리 여유가 부족했던 조합이 있어 RAM을 CPU에 둡니다.

## 4. CLIP 묶음 처리

`CGDEngine`에 적용했습니다. CG-D 원본 함수와 같은 방식으로 사진을 자르고 전처리한 뒤 최대 16개씩 묶어 처리합니다. 필터를 통과한 물체만 처리하며, 쓰지 않던 물체별 텍스트 feature 계산은 뺐습니다.

| 이전 코드와 비교 (같은 프로세스, 257장, 물체 2,796개) | 결과 |
|---|---|
| 물체 목록, 이름, 상자 | 257/257장 일치 |
| SAM 마스크 차이 | 0픽셀 |
| CLIP feature cosine 최솟값 | 0.99988 (406호), 0.99993 (412호) |

feature는 비트 단위로 같지는 않고 cosine 기준으로 거의 같습니다.

## 5. 단계별 시간

사진당 중앙값, 초, 406호 / 412호입니다. 조건이 달라 두 표를 직접 비교할 수는 없습니다.

**로컬: RTX 4060 Laptop 8 GB, RAM은 CPU** (이전 코드와 새 코드를 같은 프로세스에서 번갈아 실행, ROS 없음)

| 단계 | 이전 코드 | 새 코드, RAM 포함 | 새 코드, RAM 제외 |
|---|---|---|---|
| RAM | 1.43 / 1.60 | 1.47 / 1.62 | 0 |
| GroundingDINO | 0.32 / 0.34 | 0.33 / 0.34 | 0.30 / 0.30 |
| SAM | 0.77 / 0.77 | 0.77 / 0.80 | 0.64 / 0.67 |
| CLIP | 0.50 / 0.83 | 0.16 / 0.31 | 0.13 / 0.23 |
| 그리기 | 0.20 / 0.37 | 별도 0.03 / 0.06 | 별도 |
| **합계** | **3.15 / 3.99** | **2.67 / 3.05** | **1.06 / 1.19** |

RAM 제외에 목표 이름을 더하면 1.20 / 1.39 s입니다. 물체가 조금 늘어나 그만큼 시간이 늘어납니다.

README의 4~7초는 이전 측정이며, 지금 사진에서는 이전 코드도 3.15~3.99 s입니다. 실제 노드로 bag을 재생했을 때(사진 해독, 그리기, 저장 포함)는 중앙값 RAM 포함 3.62 s, RAM 제외 1.72 s였습니다. 406호 사진 구간에서 잰 값입니다.

**서버: A100 MIG 조각, `GSA_RAM_GPU=1`, 새 코드** (부하 약 130, 초반에는 CPU 태그 시험과 동시 실행)

| 단계 | RAM 포함 | RAM 제외 | RAM 제외 + 목표 |
|---|---|---|---|
| RAM | 0.27 / 0.25 | 0 | 0 |
| GroundingDINO | 0.88 / 0.85 | 0.87 / 0.82 | 0.88 / 0.88 |
| SAM | 1.48 / 1.60 | 1.44 / 1.55 | 1.44 / 1.60 |
| CLIP | 0.31 / 0.50 | 0.29 / 0.38 | 0.31 / 0.46 |
| **합계** | **2.99 / 3.20** | **2.63 / 2.78** | **2.66 / 2.97** |

서버에서는 RAM을 GPU에 올리면 RAM 제외로 줄어드는 시간이 약 0.3~0.4 s뿐입니다. 따라서 **서버에서 RAM을 빼는 이유는 속도보다 이름 일치**입니다. 로봇 PC에서 터널을 거쳐 시험했을 때 왕복 중앙값은 3.5 s였고, 서버 처리 시간을 뺀 나머지 약 1.3 s는 전송과 PNG 압축 등에 쓰였습니다(8장, 저희 네트워크 기준).

저희 서버의 DINO와 SAM은 말씀하신 RAM 제외 값(DINO 0.49, SAM 0.61~0.95)보다 느립니다. 이 두 단계는 코드를 바꾸지 않았으므로, 서버 부하나 MIG 조각 크기의 차이로 추정합니다. 원인을 확인한 것은 아닙니다.

## 6. 랩실 GPU 운영 제안

아래는 제안이며, 합의가 필요합니다.

| 역할 | 맡을 곳 |
|---|---|
| `cgd_server.py` 실행, 가중치, 환경 관리 | 랩실 GPU 관리 측 |
| `cgd_live_node.py --server`, SSH 터널, fusion | 로봇 PC (인지 담당) |
| 사전 지도 제작 | 기존 서버 유지. 인지 담당 |
| 코드 버전 | 저장소 커밋을 함께 지정. 통신 형식 변경 시 서버와 로봇 PC를 동시에 갱신 |

**확인이 필요한 제약**

- 설치 경로: `start_cgd_server.sh`와 `cgd_server_link.sh`는 `/data/athome/server_sync`, `/data/athome/code`를 전제로 합니다. `/data/athome/cgd_test` 설치본을 쓰려면 경로를 맞추거나 스크립트를 인자로 받게 고쳐야 합니다. 현재 설치본은 이전 커밋 3546575이므로 갱신이 필요합니다.
- GPU 사용: MIG 조각 하나에 CG-D 하나만 올립니다. `prebuild_from_bag.sh`는 `cgd_server`가 켜져 있으면 시작하지 않습니다.
- 접속 수: 서버는 한 번에 클라이언트 하나만 처리합니다. 다른 사람의 시험과 로봇 운용 시간이 겹치면 안 됩니다.
- 네트워크: 서버는 127.0.0.1에서만 받고 SSH 터널로 접속합니다. 랩실 GPU까지의 왕복 시간을 실측해야 합니다.

**저희 서버 환경:** A100 MIG 조각, `/data/athome` 아래 conda 환경 `conceptgraph`, ROS 없이 `cgd_server.py`만 실행, 포트 47000, SSH 터널 접속입니다. 저희 서버의 `/data/athome`에는 `cgd_test`가 보이지 않아 다른 환경으로 판단했습니다. 같은 서버라면 알려 주십시오.

## 한계

- 방 2개, 저장된 사진 기준 결과이며 로봇 주행 시험은 하지 않았습니다.
- 말씀하신 정차 단위 평가를 재현한 것이 아니므로, 평가 자료를 보내 주시면 같은 기준으로 맞춰 볼 수 있습니다.
- 기준표는 사진으로 확인한 것으로 현장 재확인은 하지 않았습니다.
- 406호 수건 0/7은 이번 코드 변경의 대상이 아닙니다. 저희 기준표에는 towel 범주가 따로 없어 직접 비교하지 못했습니다.
